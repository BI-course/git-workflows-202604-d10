## Team Governance & Roles

This repository adheres to the **GitHub Flow** workflow model to support structured, collaborative development. The `main` branch is protected through an enforced ruleset requiring at least **one peer-reviewed Pull Request approval** before any merge is permitted. This ensures accountability, traceability, and quality assurance across all contributions.

All development work is conducted on **feature branches**, which are later integrated into `main` via **non-fast-forward (`--no-ff`) merge commits**. This approach preserves a transparent and auditable history of the project’s evolution.

## Workflow Principles

The team follows these core principles:

- **Branch Isolation:** All changes are developed in dedicated feature branches  
- **Peer Review:** Every Pull Request must be reviewed and approved before merging  
- **Explicit Merging:** All merges use **merge commits** to preserve history (`--no-ff`)  
- **Traceability:** All commits and Pull Requests must reference their corresponding GitHub Issues  
- **Iteration-Based Development:** Tasks are aligned with defined project iterations and milestones  

---

## Collaboration Model

Daily coordination is maintained through brief stand-up discussions where team members:
- Report progress on assigned issues  
- Highlight blockers or dependencies  
- Update issue status across the project board (Backlog → Ready → In Progress → In Review → Done)  

This ensures continuous alignment with project goals and prevents last-minute integration issues.
